# ha_arm_ik merged-v13：提速 + 提高成功率（基于 v12）

入口不变（`HAArmIKSolver(...)`、`.solve(...)`），只改了 `solver.py` 和 `solver_dls.py`；`ik_candidate.py`、`ik_common.py`、
`robot_model.py` 与 v12 逐字节相同。单种子 DLS 迭代、全部约束和择优规则都没动，只改了“从哪些种子开始、按什么顺序、
什么时候换搜索范围”。五项改动都能单独关掉，全部关掉与 v12 逐值一致（有测试覆盖）。

## 1. 结论

1. **成功率提高，v12 能解的 v13 全部能解。** 一次性求解：395→400、400→400（两个模型各 400 个目标）。回放（q_prev = 上一个
   目标的解）：387→397、384→398。剩下的 5 个 v12 同样解不出，都是 JOINT_JUMP_LIMIT（只有跳变超限的解，或者超限的同时
   裕度 / 负荷也不合格）。
2. **平均耗时降低 24–37%，p90 降一半。** 均值 53→33、56→35、60→46、70→49 ms；p90 123→59、170→68、152→78、195→96 ms；
   p99 355→173、255→139、331→251、293→238 ms。中位数不变（25–34 ms）：简单目标本来前两个种子就早停，
   省下的时间都在难目标的长尾上。
3. **解的质量没有变差。** 两版都解出的目标上，v13 的择优代价均值更低（−48 ~ −100），腰部落在舒适窗内的比例略高
   （+0.5 ~ +2.3 个百分点）。
4. **路点跟踪与 v12 逐值相同。** 默认设置和 max_joint_jump_rad=0.25 两种设置下，120 个路点两臂的解逐值相同
   （480/480），每步耗时略降（0.25 设置：左 19.6→18.0 ms、右 17.1→16.4 ms）。
5. **代价是初始化慢一点。** 每个手臂模型第一次构造多花约 150 ms 建种子库（2.8 MB，只读）；同一模型的后续实例共享这份库，
   构造耗时 6 ms（v12 为 7 ms）。

## 2. 改动与设计依据

耗时分析（一次性求解，two 模型）：每个种子约 11 ms（约 30 次迭代 × 0.37 ms）。难目标慢，是因为 v12 要试很多种子；
种子的排序和取舍比单次迭代的速度影响更大。

| # | 改动 | 依据 | 默认 / 关闭 |
|---|---|---|---|
| a | **任务空间种子库**：初始化时在有效限位内均匀采样 16384 个关节角，记录末端位姿（一半样本落在舒适窗内）。每个常规阶段在 q_prev / 锁腰 / q_ready 之后，插入末端离目标最近的 3 个样本作种子（彼此关节差 ≥ 0.5 rad，只取本阶段搜索范围和跳变上限内的样本），随机扰动种子排在后面 | v12 的扰动种子以 q_prev / q_ready 为中心，目标离得远时要试很多个，种子库直接给出末端已在目标附近的关节角。选样延迟到真正排到才算，前两个种子就早停的求解不多花时间 | `dls_seed_library_size=16384`（0 关闭）、`dls_seed_library_seeds=3`、`dls_seed_library_min_separation=0.5` |
| b | **续算类求解不用种子库**：目标就在 FK(q_prev) 附近（v9 的续算判据，即路点跟踪）时，按 v12 的种子顺序搜索 | 种子库的样本是全局的。实测打开时，q_prev 附近的解只差一点限位裕度（NEAR_LIMIT），择优就会换成远处的合格解：默认设置下单步 > 0.3 rad 的次数从 1 增到 5，最大 3.05 rad | `dls_seed_library_continuation=False`（True = 续算也用） |
| c | **舒适阶段提前回退**：q_prev / 锁腰 / q_ready / 种子库种子都跑完，舒适窗内仍没有可接受解，就放开到有效限位 | 目标需要舒适窗外的腰部角度时，v12 要先在窗内跑满 max_seeds 个种子 | `dls_waist_comfort_early_fallback=True`；没有种子库时在第 `dls_waist_comfort_patience=4` 个名额后检查 |
| d | **跳变重搜**：跳变上限 ≥ π（v9 的跳变框不生效）时，如果只找到“仅跳变超限”的解，就在 q_prev ± max_joint_jump_rad 内重搜一次；舒适阶段已出现这类解时，放开阶段直接在框内搜（阶段名 `jump_box`） | 默认上限 π 时 DLS 不知道跳变上限，会收敛到要转半圈以上的解，整批被拒（JOINT_JUMP_LIMIT）。回放基准里这类目标在 v12 要跑满 10 个放开种子再失败，单个目标 300–500 ms | `dls_jump_limit_rescue=True` |
| e | **锁腰种子可达性检查**：目标到手臂首关节的距离超过“首关节到 TCP 各段长度之和”时，跳过锁腰种子（按 v7 的跳过语义：占一个名额，视为已比较） | 这个上界由三角不等式得出，不会误跳。腰锁住时够不到的目标，v12 会让锁腰种子一直迭代到停滞（平均 37 次迭代） | `dls_locked_reach_check=True` |

种子库按模型内容（URDF 的 SHA-256、活动关节、末端帧、有效限位、q_ready、舒适窗、库大小）缓存，最多 8 份，加锁，
多实例、多线程都可以共享。

**没有做单次迭代的微优化。** 一次迭代里 Pinocchio 只占约 10%，其余是 Python / NumPy 开销（SNS 26%、次任务 24%、
代价项 19%）。在保持与 v12 逐位一致的前提下，微优化大约只能省 10–15%。要明显再提速，需要把单种子循环编译化
（预计 3–5 倍），这要单独实现、单独验证。

## 3. 数据

合成模型，Pinocchio 4.1.0，`load_max_seeds=10`，`dls_max_iter=500`，单次时间预算 0.5 s。目标由限位内（内收 0.02 rad）
均匀采样的关节角做 FK 得到，必然可达：full 200 个、tool_dir 100 个、tool_cone 100 个。two = 双臂合成 URDF 的
左臂 + 腰（限位接近真实人形），wide = tests/fixtures 模型（±3 rad）。回放组的 q_prev 来自 v12 链式求解的结果，
两版输入完全相同。v12 的数据由 v12 包实际运行得到。

| two 一次性 | 395 → 400 | 53.2 → 33.3 | 25.4 → 25.1 | 123 → 59 | 355 → 173 | 473 → 278 | −48.2 | +0.020 |
| wide 一次性 | 400 → 400 | 56.0 → 35.4 | 27.2 → 26.0 | 170 → 68 | 255 → 139 | 314 → 161 | −99.8 | +0.005 |
| two 回放 | 387 → 397 | 59.7 → 45.6 | 31.6 → 32.8 | 152 → 78 | 331 → 251 | 494 → 358 | −84.0 | +0.023 |
| wide 回放 | 384 → 398 | 69.7 → 48.8 | 33.0 → 33.6 | 195 → 96 | 293 → 238 | 502 → 289 | −86.5 | +0.005 |

失败码：v12 two 5 × NO_VALID_POSE_OR_PHYSICS；two 回放 10 × JOINT_JUMP_LIMIT + 3 × NO_VALID_POSE_OR_PHYSICS；

dC = 两版都解出的目标上的择优代价差均值（v13 − v12，负数表示 v13 更优）；inC = 腰部落在舒适窗内的比例差。

## 4. 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `dls_seed_library_size` | 16384 | 种子库样本数；0 / None / False 关闭（4096 时首次构造约 45 ms，四组基准合计少解出 3 个） |
| `dls_seed_library_seeds` | 3 | 每个常规阶段插入的种子库种子数；0 = 建库但不用 |
| `dls_seed_library_min_separation` | 0.5 | 种子库种子之间、以及与本阶段已跑种子之间的最小关节差（∞-范数，rad） |
| `dls_seed_library_continuation` | False | 续算类求解是否也用种子库 |
| `dls_waist_comfort_early_fallback` | True | 舒适阶段提前回退 |
| `dls_waist_comfort_patience` | 4 | 没有种子库时，提前回退检查点放在第几个名额之后 |
| `dls_jump_limit_rescue` | True | 跳变重搜 |
| `dls_locked_reach_check` | True | 锁腰种子可达性检查 |

完全回到 v12 的行为：`dls_seed_library_size=0, dls_waist_comfort_early_fallback=False, dls_jump_limit_rescue=False,
dls_locked_reach_check=False`。

新增诊断字段（`last_load_diagnostics["search"]`）：`library_seeds_queued`、`library_skipped_continuation`、
`locked_seed_unreachable`、`jump_limit_rescue`、`jump_limit_rescue_early`、`comfort_patience_stop`；`per_seed` 中
新增种子类别 `library` 和阶段 `jump_box`。版本号是 `merged-v13`。

## 5. 验证

- Pinocchio 4.1.0 和 3.9.0 各跑 180 项测试，全部通过（`validation_pin4_1_0.*`、`validation_pin3_9_0.*`）。
- 新增 `tests/test_v13_changes.py`（23 项）：种子库（形状、限位、只读、位姿 = FK、可复现、选样规则、多实例共享）、
  种子顺序、续算类求解不用种子库（跟踪基准第 38 个路点）、舒适阶段提前回退、可达性上界的严格性、跳变重搜（两个回放
  基准里 v12 失败的目标）、配置校验，以及五项全关与 v12 逐值一致（`tests/reference/solver_v12.py` 是 v12
  `solver.py` 的原样副本）。
- `tests/test_v7_speed.py` 有 3 个用例显式关掉了可达性检查：这几个用例的目标超出锁腰时的手臂可达范围，测的是锁腰种子
  本身的流程（腰部负荷释放、v7 种子顺序）。

## 6. 需要你确认

1. **数据来自合成模型。** 换成真实 URDF 后，建议用 `bench/v13/stress.py` 和 `compare.py` 复测一次（v12 / v13 各跑一遍，
   成对比较）。
2. **初始化多约 150 ms / 臂，是否可以接受？** 如果启动时间敏感，可以设 `dls_seed_library_size=4096`（首次构造约 45 ms，四组基准合计少解出 3 个）。
3. **跳变重搜得到的解可能正好落在 q_prev ± max_joint_jump_rad 的边界上。** 这是合法解，但单步就等于上限值。
4. **路点跟踪仍建议设 max_joint_jump_rad**（例如 0.25），与 v9 / v12 的建议相同。
5. **还要更快的话，下一步是把单种子 DLS 循环编译化**，需要单独实现和验证。
