## 0. 腰部窗口建议（结论）

1. **硬窗口 `dls_virtual_half_windows` 不设。** 硬窗口外的目标直接无解。只有确实存在物理 / 安全原因（线缆、结构干涉、碰撞区）时才设，数值按那个原因定。
2. **用 v8 默认的舒适窗 `dls_waist_comfort="auto"`，不需要配置。** 它是偏好，不是约束：
   - 初始化时由 URDF 质量 / 质心和 q_ready 算出（第 1 节）；
   - 只用于大位移的“重新定位”求解，路点跟踪（小位移续算）不加窗，与 v7 相同（第 2 节）；
   - 窗内没有满足全部硬约束的解时，自动放开到真实限位重试，不会减少可解目标。
3. 合成模型上的推导结果：

   | 关节 | 类别 | 舒适窗 | 相对 q_ready | 边界由谁决定 |
   |---|---|---|---|---|
   | Hip_Link1（绕 y，俯仰） | 重力类 | [−0.671, +0.337] rad（−38.5° ～ +19.3°） | −41.3° / +16.4° | +侧：负荷判据（\|τ\| 到 61.3 N·m）；−侧：质心判据 |
   | Body_Link（绕 z，偏航） | 重力无关 | [−1.471, +1.671] rad | ±90° | 朝向判据 |

4. 真机上：初始化后调用 `print_info()`（或 `verbose=True`），核对 `waist comfort window ...` 两行。窗口取决于 URDF 惯量参数；参数不准时用显式 `{"Hip_Link1": 半窗, "Body_Link": 半窗}`（rad，以 q_ready 为中心）覆盖。不建议设得很窄：窄窗 {0.2, 0.4} 的次任务代价高 0.4～8.6%，并回退 7 次（第 4 节）。

## 1. 舒适窗怎么推导（第一性原理）

腰部承载整个上半身，偏转腰部的代价不在关节角本身，而在两件事：

- **静态重力矩。** 其它关节固定时，转动腰关节只是让它的子树（上半身 + 双臂）绕轴刚性转动，所以重力矩是精确正弦 τ(θ) = C·sin(θ − φ)（符号随轴向）。C = 子树质量 × g × 质心到轴的垂距 × sin(轴与重力夹角)，即“上半身放平”时的最大重力矩；φ 是质心正好在轴正上方的平衡角。τ 同时等于“重量 × 质心水平力臂”，所以它既度量电机负荷，也度量质心偏移。
- **躯干朝向。** 轴与重力夹角 < 30° 的腰关节（偏航）几乎没有重力矩，但转过 90° 后胸前（另一只手、头部相机）背离前方工作区，这类目标应该由底盘转向完成。

窗口定义（s = 0.7，与 LoadPolicy 的 soft_ratio 同义，即只用 70% 的能力；配置了 `load_soft_ratio` 时跟随）：

| 类别 | 窗口 = 包含 q_ready 的连通区间内同时满足 |
|---|---|
| 重力类（俯仰 / 侧倾） | 负荷：\|τ(θ)\| ≤ max(s·min(C, A), \|τ(q_ready)\|)，A = 容许力矩（`load_allowable_efforts`，没有则用 URDF effort）<br>质心：\|τ(θ) − τ(q_ready)\| ≤ s·C，即上半身质心相对 q_ready 的水平位移 ≤ s × 质心到轴的垂距 |
| 重力无关类（偏航） | q_ready ± 90° |

两类都再与 q_ready ± 90°、真实限位求交。

- 直立且前后平衡的上半身，两条判据都给出 φ ± asin(0.7) = φ ± 44.4°。
- 合成模型的 q_ready 已经偏离平衡角 28°（τ_ready = −41.1 N·m，C = 87.5 N·m，阈值 0.7 × 87.5 = 61.3 N·m）：往重的一侧负荷判据先到（+16.4°），往另一侧越过平衡点后由质心判据限住（−41.3°）。
- A < C 时负荷判据更窄（该关节负载率 ≤ s）。
- 推导时会校验正弦律；校验不通过的关节不设窗，并在 `solver.waist_comfort_info` 里标 `gravity_check_failed`。

## 2. 舒适窗只用于“重新定位”

判定：目标相对 FK(q_prev) 的主任务误差（与 DLS 同一度量）位置 > 0.1 × 臂展（合成模型 0.115 m）或姿态 > 0.1 rad，判为**重新定位**，走两阶段搜索：

1. 阶段 1：有效限位 ∩ 舒适窗内搜索，种子顺序与早停规则同 v7；
2. 阶段 1 没有“可接受”候选（位姿达标、跳变不超限、限位裕度足够，strict 下负荷合格）时进入阶段 2：放开到有效限位，种子依次为 q_prev → 阶段 1 误差最小的终点（贴在窗边，从这里续算只多用必要的腰部）→ q_ready → 与 v7 相同的随机扰动。

否则判为**续算**（路点跟踪）：不加窗，结果与关闭舒适窗逐值一致。

为什么这样分：早期方案每次求解都加窗。腰部大幅跟踪（239 个路点，俯仰目标到 −1.44 rad，远超窗口）加 `max_joint_jump_rad=0.25` 时只成功 59/239：窗口先把腰卡在窗边，手臂补偿到极限才放开，腰部瞬变 0.35 rad，超过跳变上限。软边界（势垒）方案也试过，跟踪表现更差，已放弃。按类别分开后是 239/239，单步最大 0.061 rad，与 v7 一样。基准里一次性目标全部判为重新定位（200/200），跟踪路点全部判为续算（119/119、239/239）。

## 4. 实测（合成 9 轴模型，Pin 4.1.0，与 v7 同一批目标）

H = v7 的 strict 零空间次任务代价（同一把尺子评估所有版本，越低越好）；俯仰 / 偏航偏离 = |q − q_ready|，单位 rad。

| 目标集 | 成功 v7 / v8 | 俯仰最大偏离 v7 → v8 | 俯仰 > 0.8 的个数 | 偏航最大偏离 v7 → v8 | H（v8 相对 v7） | 耗时 ms v7 → v8 |
|---|---|---|---|---|---|---|
| near_full ×40 | 40 / 40 | 0.467 → 0.466 | 0 → 0 | 0.556 → 0.554 | +1.15%（5 个变差） | 12.8 → 13.5 |
| far_full ×60 | 60 / 60 | **2.109 → 0.711** | 7 → 0 | 1.546 → 1.555 | −2.06% | 20.8 → 22.7 |
| far_tool_dir ×50 | 50 / 50 | **0.956 → 0.707** | 5 → 0 | 1.176 → 1.182 | −2.28% | 27.4 → 28.8 |
| far_tool_cone ×50 | 50 / 50 | **1.786 → 0.721** | 3 → 0 | 1.953 → 1.557 | −2.89% | 27.4 → 30.5 |
| 路点跟踪 ×119 | 119 / 119 | 0.143 → 0.143 | 0 → 0 | 0.266 → 0.266 | 0 | 8.3 → 8.2 |

- 腰部改用偏航多、俯仰少（偏航 > 0.8 rad 的个数 far 7 → 8、cone 6 → 8），这是预期的取舍：偏航不承重。负荷峰值略降（far 0.082 → 0.077），限位裕度 < 0.1 的个数 far 6 → 3。
- 关闭舒适窗的 v8 相对 v7：H near −0.01%、far +0.89%、tool_dir −1.75%、cone −0.95%（第 3 节的修正带来的变化）。
- 窄窗 {Hip_Link1: 0.2, Body_Link: 0.4}：H +8.6 / +5.5 / +0.4 / +3.4%，回退 7 次，仍全部求解成功。
- 耗时：一次性目标比 v7 慢 5～11%（两阶段搜索 + 更长的姿态整理），跟踪持平；比 v6 快 1.6～2.8 倍。
- 腰部大幅跟踪（`bench/v8/track_waist.py`）：v7 与 v8 表现相同。不设跳变上限时两版单步最大都是 2.47 rad（见第 6 节最后一条），设 0.25 后两版都是 239/239、单步最大 0.061 rad。

明细见 `bench/v8/quality_pin4_1_0.txt`、`paired_timing_pin4_1_0.txt`、`track_waist_pin4_1_0.txt`。

## 5. 配置项、诊断与恢复 v7 行为

| 配置项 | 默认 | 说明 |
|---|---|---|
| `dls_waist_comfort` | `"auto"` | `"auto"` 按第 1 节推导；`None` / `False` / `"off"` 关闭；`{腰关节名: 半窗 rad}` 以 q_ready 为中心显式指定（未列出的腰关节不设窗）；其它值抛 ValueError |
| `dls_waist_comfort_continuation_tol` | `None` | `(pos_m, ori_rad)`，重新定位 / 续算的分界；`None` = (0.1 × 臂展, 0.1 rad)；`(0, 0)` = 几乎每次求解都加窗 |
| `dls_virtual_half_windows` | 不设 | 硬约束，与舒适窗独立，含义同 v7 |

诊断：

- `solver.last_load_diagnostics["waist_comfort"]`：`enabled`、`regime`（"reposition" / "continuation"）、`applied`、`fallback_to_full_bounds`、`comfort_seeds`、`full_bounds_seeds`、`selected_stage`、`selected_in_comfort`；
- strict 模式另有 `last_load_diagnostics["search"]["waist_comfort"]`；每个种子的 `per_seed[i]["search_stage"]`；
- `solver.waist_comfort_info`：每个腰关节的推导明细（类别、τ_ready、C、平衡角、阈值、边界由哪条判据决定）。

恢复 v7 的搜索行为：`config={"dls_waist_comfort": None}`，并把 `solver_dls.MAX_SETTLE_EXTRA_ITERS`、`SETTLE_PATIENCE` 改回 15、2。第 3 节的其它修正属于 bug 修复，没有开关。

## 6. 验证与上线前确认

- `run_validation.py`：Pinocchio 4.1.0 / 3.9.0 各 127 项测试全部通过（`validation_pin*.json/txt`），其中 v8 新增 21 项（`tests/test_v8_changes.py`）：窗口推导（正弦律、边缘恰好取等、平衡态 φ ± asin s、偏航 ±90°、容许力矩收窄、零重力、正弦校验失败）、配置校验、两阶段回退、求解类别（续算与关闭逐值一致、腰部大幅跟踪加跳变上限全程连续）、臂展、off 模式质心参考、容差、同名 URDF。
- 没有验证：真实 URDF 与质量参数（窗口数值直接依赖它）、你们真实的 ik_common / ik_candidate（这里用测试替身）、ROS 2 / MoveIt / 真机；Python 3.12 只做了语法检查。
- 窗口只在初始化时按 q_ready 计算一次；推导时非活跃关节取 `q_template`（没有则 URDF 零位）。末端负载或工具变化后需要重新创建求解器。
- 既有行为（v6 起，v8 未改）：择优是负荷优先（先取负荷峰值容差带，再看连续性），不设 `max_joint_jump_rad` 时路点之间可能换到远处的解（上面的跟踪测试单步 2.47 rad）。做轨迹跟踪时建议设 `max_joint_jump_rad`（按路点间距取，例如 0.25 rad）。
